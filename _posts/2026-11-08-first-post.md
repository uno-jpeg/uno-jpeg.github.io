#### **Parser Discrepancy на пальцах**

*(Кстати, если кто не знает, **парсер** - это, можно сказать, программа, которая читает входящие данные. Грубо говоря так.)*

Приложение работает по грубо говоря такой схеме:
`Пользователь -> Запрос -> "Контроллер" -> "Исполнитель"`

1. Пользователь - Я
2. Запрос - То, что посылаю в программу нажатием на кнопку
3. Контроллер - Проверяет, что я отправил:
   Если что-то запрещенное (Опция ACCESS SECURE DATABASE) - Отказывает в доступе.
   Если разрешенное (Опция SCAN COSMIC ANOMALY) - Передает запрос исполнителю
4. Исполнитель - Исполняет.

И вся идея в том, что КОНТРОЛЛЕР и ИСПОЛНИТЕЛЬ могут быть настроены по-разному и читать одно и то же сообщение, по разному его интерпретируя.
Простейший пример.
Я отправляю запрос:
```
А = 1
а = 2
```
Как это интерпретируете вы? 
Чему равно а? 
Или А? 
Для вас а маленькая и А большая - одно и то же, или разное? 

И для разных парсеров ответ может быть разный: Для кого-то одно и то же, а для кого-то - Абсолютно два разных символа.
Это называется **РЕГИСТРОЗАВИСИМОСТЬ**.

Еще пример. Допустим, для вас а = А, ведь это одна и та же буква. Вы интерпретируете это так. Хорошо. Тогда если вы увидите запись:
```
a = 1
a = 2
```
Чему для вас будет равно а?
Вы сначала прочитаете все заданные данные, или как только получите значение а(1), сразу перестанете читать всё остальное?
От вашего поведения будет зависеть, чем будет являться а. 
Все дело в интерпретации, и, как вы уже, наверное, поняли, каждый парсер смотрит на это по-своему.
Это называется **ПОСЛЕДОВАТЕЛЬНОСТЬ**. Наверное. Хз. Может и нет. Но я это так назвал. )))))

Короче, вот в этом-то и вся суть. Представим, как парсеры интерпретируют то, что в них прилетело:
```
Контроллер: а = А (Регистр не важен); а = 2 (Читает до конца)
Исполнитель: а = а (Регистр важен); а = 2 (Читает до конца)
```
Пока просто имейте это ввиду. Надеюсь, ввел вас в курс дела.

Если перед нажатием на кнопку INITIATE SCAN я выбираю ACCESS SECURE DATABASE, Вот такое тело запроса отправляем на сервер. (На HTTP-Header пофиг, не хочу вас грузить лишним):

Посмотрим, как это реализовано в коде (С комментариями):
```
    switch requestData.Action { ### Смотрит, что в запросе

    case "getcosmic": ### Если мы нажали на scan cosmic anomaly:
        resp, err := http.Post("http://localhost:8081/execute", "application/json", bytes.NewBuffer(body)) ### Запрос передается исполнителю

        if err != nil { ### Это GO-Специфика: Если не указать, что происходит при ошибке, программа не запустится. Не обращайте внимания особо, технический момент.
            log.Printf("Failed to reach cosmic scanner: %v", err)
            http.Error(w, "Scanner offline", http.StatusInternalServerError)
            return
        }
        
        defer resp.Body.Close()
        io.Copy(w, resp.Body)
        
    case "getSecureCode": # Если пользователь нажал на ACCESS SECURE DATABASE
        w.Write([]byte("Access denied: Invalid security clearance")) # Разворачиваем его
    default:
        http.Error(w, "Invalid command", http.StatusBadRequest)
    }

}
```

Короче, еще раз. Логика пока такая: 
Если парсер (Читающая программа) на контроллере видит слово "getSecureCode" (А именно этот запрос и отправляется, когда мы нажимаем на кнопку "access secure database"), то он выдает нам ошибку.

Если видит "getcosmic", то пропускает дальше на бэкенд, где обработка выглядит так:
```
    if data['action'] == "getcosmic": # Если 'action' = 'getcosmic'

        anomaly = random.choice(COSMIC_ANOMALIES) # Готовлю случайную картинку

        return jsonify(anomaly) # Возвращаю результат

    elif data['action'] == "getSecureCode": # Если 'action' = 'getSecureCode'

        return jsonify({ #Возвращаю FLAG

            "flag": os.getenv("FLAG", "HTB{flag_not_set}"),

            "name": "Captain's Log",

            "src": "https://images.unsplash.com/photo-1534447677768-be436bb09401?w=600"

        })
```

Отлично. То есть, если запрос пройдет, то нам вернется FLAG. Как раз то, что нам и нужно.

Итак, вкратце разберемся, что произошло:
1. "Проверяющий" парсер увидел, как к нему прилетел json, с, как ему показалось, одинаковым ключом `action` (Ему было без разницы на регистр). Он поступил так:
